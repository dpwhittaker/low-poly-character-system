# M1 bake-off: results and decisions (2026-10-13)

The probes of PLAN §3.4, run during M1. Scores are 1–5, weighted per PLAN §3.4: visual 40 %,
deformation 20 %, automation 15 %, budget 10 %, iteration speed 15 %. Visual and
deformation scores are my judgement from the renders, **not** the blind A/B the plan asks
for. The user's M1 sign-off is the real visual gate.

## P1 Base body: (B) MakeHuman CC0 proxy topology wins

| approach | visual | deform | automation | budget | iteration | weighted |
|---|---|---|---|---|---|---|
| **B-proxy:** `female1605` (human-designed CC0 quads) + 23 authored cut lines | 4 | 4 | 5 | 4 | 4 | **4.15** |
| B-decimate: M0's weighted collapse decimation of the MakeHuman mesh | 3.5 | 2.5 | 4 | 4 | 4 | 3.5 |
| (A) direct modelling from primitives | not run | | | | | |
| (D) code-generated (control) | not run | | | | | |

- **Why B-proxy:**
  - The proxy is bound to the MakeHuman base mesh, and that binding is linear. So all 658
    targets (macros, ages, sliders, house style) transfer **exactly**: 0.0003 mm against MPFB's
    own fit (SPEC V18).
  - One topology covers ages 1→70 with correct toddler and child proportions
    (`P1/ages_one_topology.jpg`).
  - The designed quads deform well at elbows and knees (`P4/joint_closeups.jpg`).
- **Cut lines:** the proxy lacks complete loops where garments end. So the 23 standard cut
  lines are authored by plane cuts with snapping, and every one is a closed loop (V19,
  `P1/cut_lines_bands.jpg`).
- **Not run:** (D) failed twice in this workspace's earlier projects (PLAN §2). (A) was not
  attempted because (B) met the bar. If the user rejects the body, (A) is the next probe.

## P2 Faces: geometric features (S1) with authored brows

- **Style:** chosen at M0 by the user (S1 smooth: all vertex color, features are geometry).
- **Brows:**

  | approach | result |
  |---|---|
  | MakeHuman alpha brow cards, cut into geometry (M0 recipe) | sat low and slanted toward the nose; every face read stern |
  | **authored tapered strips**, projected onto the brow ridge | soft / straight / bold; read calm and friendly |

  Authored strips win (`P2/authored_brows.jpg`).
- **Identity:** three identities from sliders + heritage + skin + hair + brows
  (`P2/three_faces.jpg`). The 25 region and face sliders all transfer from MakeHuman.
- **Body range:** MakeHuman's max weight is mild, so a body-fat composite extends it
  (`P2/weight_range.jpg`, SPEC R35).

## P3 Garments: (A) authored on the body shell wins

| approach | visual | deform | automation | budget | iteration | weighted |
|---|---|---|---|---|---|---|
| **A: body-band shell + relax + clearance + opening extensions/hems** | 4 | 4 | 4.5 | 4 | 3.5 | **4.0** |
| C: MakeHuman CC0 garment (`female_casualsuit01`), decimated to the same budget, rebound | 3.5 | 3.5 | 3.5 | 4 | 3 | 3.5 |

- **Why A** (`P3/A_vs_C.jpg`):
  - Openings land exactly on cut lines, so bands hide cleanly and no base layer shows at the
    neckline or hem.
  - The authored collar, hems and cuffs carry the recolor channels.
  - The layering rules (D2 clearance against the body *and* the layer below) are built in.
- **Where C wins:** its silhouettes are more natural, being designed by a human. MakeHuman
  clothes stay useful as **shape reference**.
- **Built with A:** tee (untucked), straight jeans, an open work jacket over the tee, chunky
  sneakers.
- **Hair:** from MakeHuman CC0 hair (ponytail, bob, short), solidified into shells.
- **Results:** every garment fits every age and weight through the binding, and holds in
  motion (`P3/layered_outfit_motion.jpg`).
- **Live:** `tee_mh` / `jeans_mh` are approach C, kept in the catalog so the user can compare
  them in the creator.

## P4 Deformation

- **Rig:** MPFB `game_engine` weights, transferred through the proxy binding, plus twist
  bones driven from hand / upper-arm roll.
- **Joints:** elbows, knees and shoulders hold volume in crouch, run, arms up and sit, bare
  and dressed (`P4/stress_poses.jpg`, `P4/joint_closeups.jpg`).
- **Known defect:** in `arms_crossed` the forearms pass through each other and the bust.
  That's a body-shape contact problem, assigned to D10 contact IK (M4).
- **Not yet run:** the plan's comparison against Blender heat weights.

## P5 Rigid accessory: not run

Hat, glasses and bag are not in the M1 gate set. Deferred to M3 with the rest of the catalog.

## P6 Animation

Run by a worktree agent; merged. See `P6/P6.md`.
- **CMU** wins idle, walk, arms_up and wave.
- **Mesh2Motion** wins sit, sit_down, run, crouch and arms_crossed.
- **KayKit** loses all.
- **Licence:** CMU allows free use, but its terms forbid reselling the data "even in
  converted form", and ask for a credit line.

## P7 Pipeline: pass

The path works end to end: MakeHuman → Blender scripts → body pack + item packs + clip GLB →
TypeScript assembler → one merged mesh and one draw call per character, in the browser.
19 Node tests cover the arithmetic: macro weights, body fit, skeleton, item fit, clips.

## P8 Interface: persistent Blender (MCP backend) for iteration, the same scripts for the build

| interface | used for | results |
|---|---|---|
| persistent Blender via `tools/blender-exec.py` | all body and item work | each pipeline script runs in **seconds to ~1 min**: extract ~5 s, pack ~15 s, garments 20–60 s. Overran the 300 s socket once (B6). After a timeout, `blender-mcp.sh restart` |
| batch `blender -b` | the animation agent | worked; bit-identical reruns |

Every script wipes its scene and runs either way, so the persistent session is for speed and
the scripts are the reproducible build.
